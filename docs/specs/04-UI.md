# UI — Small generic component system and layout contracts

**Status:** Authoritative P1 baseline · **Authority:** reusable UI primitives, hybrid CSS + Tailwind rules, component composition, responsive behavior. Page content belongs to `03-UX.md`; no domain-specific component tree is mandatory.

## 1. Philosophy

**Small vocabulary, broad composition:** use `Page`, `Stage`, `Panel`, `Row`, `Grid`, `Stack` with semantic CSS classes for surfaces and controls, and Tailwind for layout/responsive composition. Extract additional controls only when repeated meaningful behavior warrants it. Avoid creating a React component for every titled concept (`ActivityMetricsCard`, `ProgramSchedulePanel`, `WorkoutSection`, etc.). Domain state lives in hooks/services and DTO-driven view data; styling can be adjusted in-place through `className`.

- **Structure from primitives**, **visual identity from token-driven CSS**, **layout from Tailwind**, **behavior from a few specialized controls**.
- Prefer **composition** over long chains of layout props, theme variants, slot APIs, polymorphic `asChild` systems, or nested domain wrappers.
- Use `Panel` only for a real interaction (a form, session controls, an editor block). Content sections are a section heading plus content on the page background, not a box. Content items (Program and Activity rows, media tiles) use the shared patterns in §4a. There is no generic `Card` or `Shell` abstraction.
- Generic primitives are allowed to be boring. Custom element/layout code is appropriate where extraction would be harder to read.

## 1a. Relationship to shared factory components

`Page`, `Stage`, `Panel`, `Row`, `Grid`, and `Stack` are the layout vocabulary and live in `apps/web/src/components/ui/`. Shared controls: `Button`, `Input`, `Textarea`, `Select`, `Avatar`, `EmptyState`, `Skeleton`, `Spinner`, `Form`. Not used: sidebar/bottom-nav `Shell` (`03-UX.md` §2 has no primary navigation).

## 1b. Hybrid styling architecture

| Layer | Owns | Lives in |
|---|---|---|
| Design tokens & themes | Color, type, spacing, radius, elevation, motion scales; light/dark palettes | `apps/web/src/styles/tokens/`, `themes/` |
| Semantic component CSS | `.page`, `.stage`, `.panel`, `.btn`, `.input`, `.select`, `.form`, widget classes | `apps/web/src/styles/components/`, `widgets/` |
| Tailwind | Flex/grid, gaps, responsive visibility, one-off layout tweaks | Utility `className` on primitives and pages |
| React primitives | Semantics, a11y, behavior; apply semantic classes | `apps/web/src/components/ui/` |

Theme switching remains class-on-`<html>` (`.dark`). Components consume semantic tokens (`var(--color-*)`, `var(--space-*)`, …), never hardcoded palette hex/hsl in TSX. Do not mass-replace Tailwind layout utilities with CSS; migrate page chrome onto semantic classes page by page.

## 2. Component contracts

| Component | Minimal props | Responsibility | Avoid |
|---|---|---|---|
| `Page` | `children, className` | Screen width (one preset: `.page--focused`, `.page--content`, `.page--wide`), vertical scrolling, responsive gutters | Data fetching, route decisions, its own `max-width` |
| `Stage` | `children, className` | Centered single-focus task with consistent spacing (`.stage`) | Owning wizard logic |
| `Panel` | `children, className` | Contained interface section / grouping (`.panel`) | Hardcoding a title/action schema; using for list content items |
| `Row` | `children, className` | Flex aligned items; wrap via Tailwind | Domain-specific metadata slots |
| `Grid` | `children, className` | CSS grid for buttons, cards, thumbnails | Media service logic |
| `Stack` | `children, className` | Vertical flex stack with gap | Business semantics |

Suggested default JSX definitions (forward normal element props, merge class names, do not introduce new prop DSL):

```tsx
import type { HTMLAttributes, PropsWithChildren } from 'react';
import { cn } from './cn';

type Props = PropsWithChildren<HTMLAttributes<HTMLDivElement>>;
export const Page = ({className, ...props}: Props) =>
  <main className={cn('page', className)} {...props} />;
export const Stage = ({className, ...props}: Props) =>
  <div className={cn('stage', className)} {...props} />;
export const Panel = ({className, ...props}: Props) =>
  <section className={cn('panel', className)} {...props} />;
export const Row = ({className, ...props}: Props) =>
  <div className={cn('flex items-center gap-3', className)} {...props} />;
export const Stack = ({className, ...props}: Props) =>
  <div className={cn('flex flex-col gap-3', className)} {...props} />;
export const Grid = ({className, ...props}: Props) =>
  <div className={cn('grid gap-2', className)} {...props} />;
```

`cn` merges class strings and resolves conflicting Tailwind utilities (e.g. `clsx` + `tailwind-merge`). Use accessible real controls: `button`, `input`, `select`, `label`, `dialog`/headless primitives where appropriate, not clickable divs. The snippet is illustrative; tests enforce semantics.

| `AvatarStack` | Compact avatars and counts; accessibility names | Collaborators, Group |
| `CollaboratorRow` | Avatars, permitted completion, reaction control; one standard compact row | Activity occurrence, Group |

Only `CalendarSurface`, media capture/playback, and accessibility-heavy picker/composer are likely to deserve deep internals. Every other control should have a narrow API and no arbitrary override factories.

## 4. Design tokens: semantic, CSS-owned, Tailwind-bridged

**Product:** Program Guru.

**Visual direction:** an editorial, media-rich application with the working density of a productivity tool. Closer to a streaming catalog and a creative workspace than a SaaS dashboard. **Content gets the space; controls get out of the way.**

| Quality | Rule |
|---|---|
| Canvas | Deep charcoal is the default design target. Light mode stays fully supported: every token has a light value, and every screen must pass in both. |
| Color | Mostly neutral. Blue (`--color-accent`) is reserved for actions and focus. Participation states have their own tokens. Category color identifies a Category and never stands in for a state. |
| Typography | Confident, readable, moderate. No marketing-size headlines; no labels under 12px. |
| Imagery | Prominent where it informs (Program hero, media), absent where it doesn't. Every image uses a standard ratio and the one fallback chain (§4a). |
| Layout | Spacious on content pages, compact on working surfaces (Calendar, My Programs table, editor). |
| Surfaces | Few borders. Sections sit on the page background; stronger containers are reserved for interactions. |
| Navigation | Restrained: one app header, no primary navigation (`03-UX.md` §2). |
| Mobile | Designed for, not compressed from desktop: stacked actions, horizontal media rails, full-screen sheets. |

Consistency means shared components, tokens and principles, not identical layouts. Calendar keeps generous day cells, My Programs a dense table, the Activity page focused session controls.

No faux HUD, gratuitous gradients or purple theme defaults. Hardcoded palette classes (`bg-blue-600`, `text-white/80`, `bg-neutral-950`) are not allowed in shared components; use tokens. Image overlays may use black/white alpha scrims only for text legibility on photography.

Token files live under `apps/web/src/styles/`. Semantic color names are fixed so pages never invent their own:

- **Surfaces:** `--color-bg` (page), `--color-surface` (raised), `--color-surface-raised` (interactive/hover), `--color-surface-muted` (subtle fill). **Divider:** `--color-border`. **Text:** `--color-text`, `--color-muted`. **Action:** `--color-accent`, `--color-accent-fg`, `--color-focus`. **Feedback:** `--color-success`, `--color-attention`, `--color-danger`.
- **Participation states:** `--color-status-planned`, `--color-status-active`, `--color-status-completed`, `--color-status-paused`, `--color-status-unavailable` (Tailwind `text-status-*`, `bg-status-*/15`). Always paired with a text label or icon. Calendar, My Programs, the Activity page and Group use these and nothing else for state.
- **Scales:** `--space-*`, `--radius-*`, `--text-*` / `--leading-*`, `--shadow-*`, `--duration-fast` (120ms), `--duration-base` (200ms), `--ease-out`. Disabled under `prefers-reduced-motion`.
- **Type:** display face for titles only; UI/body sans; mono for dates/day numbers. Do not encode “primary” with huge headings. The scale stops at `--text-4xl` (2.5rem). Use roles, not raw sizes:

  | Role | Token | Use |
  |---|---|---|
  | Hero title | `--type-hero-title` (fluid 1.75–2.5rem) | Program and Profile heroes only |
  | Page title | `--type-page-title` (1.75rem) | One `h1` per page |
  | Section title | `--type-section-title` (1.375rem) | `h2` section headings |
  | Content title | `--type-content-title` (1rem, semibold) | Row, tile and media titles |
  | Metadata | `--type-meta` (0.875rem, muted) | Counts, durations, creator, dates |
  | Caption | `--type-caption` (0.75rem) | Badges, timestamps, legal. Nothing smaller |
- **Width:** the app header spans the viewport with responsive gutters. Every page uses exactly one preset and no page-specific `max-width`:

  | Preset | Token / class / Tailwind | Pages |
  |---|---|---|
  | Focused | `--width-focused` 42rem · `.page--focused` · `max-w-focused` | Program editor steps, Add a Program, Settings, auth |
  | Content | `--width-content` 72rem · `.page--content` · `max-w-content` | Program page, Activity, Group, Profile, Discover, Media |
  | Wide | `--width-wide` 1920px · `.page--wide` · `max-w-wide` | Calendar, My Programs table |

  Gutters: 16px under 640px, 24px from 640px. Vertical rhythm between page sections: `--space-8` (mobile `--space-6`). `--page-max` (80rem) remains only until each page moves to a preset.
- **Radius:** buttons use `--radius-control`; panels/cards use `--radius-panel`; thumbs use `--radius-media` or circle.
- **Media ratios:** four only.

  | Ratio | Token / Tailwind | Use |
  |---|---|---|
  | 16:9 | `--ratio-hero` · `aspect-hero` | Program and Activity heroes, Program covers in discovery, video |
  | 4:3 | `--ratio-preview` · `aspect-preview` | Content previews: Activity rows, Related Media tiles |
  | 1:1 | `--ratio-thumb` · `aspect-thumb` | Media grids, list thumbnails, avatars |
  | 3:1 | `--ratio-profile-cover` · `aspect-profile-cover` | Profile covers |

  Images use `object-cover`, lazy loading, a `--color-surface-muted` placeholder while loading, and the §4a fallback on failure. Hover may lift the frame or brighten the image; it never scales layout. A hero image must not occupy more than about 60% of the first viewport on desktop.
- **Tailwind bridge:** map semantic colors and fonts to utilities (`bg-surface`, `text-muted`, `font-display`, `duration-fast`) for residual layout composition. Prefer semantic CSS classes on shared controls.
- **Icons:** ~16 for rows, ~20 for standalone choices; icons clarify action, never replace accessible name.
- **Breakpoints:** mobile-first, Tailwind's four only: `sm` 640px, `md` 768px, `lg` 1024px, `xl` 1280px. Hand-written CSS uses the same values (`min-width: 640px` / `max-width: 639.98px`); no other breakpoint values. Option grids `grid-cols-2`; media thumbs `grid-cols-5`+; Calendar: week strip + selected day on mobile, seven columns on `md+`.
- **Radius:** controls `--radius-control`; panels and content tiles `--radius-panel`; media inside a tile `--radius-media`. Heroes may use `--radius-panel` at most; no 24px+ radii.
- **Interactive states:** hover raises to `--color-surface-raised`; focus is a 2px `--color-focus` ring; selected uses `--color-accent` fill (`--color-accent-fg` text). Same on every screen.
- **Touch / a11y:** ≥44px targets; visible focus rings via `--color-focus`; non-color status distinctions; AA contrast for text and selected states.

Calendar widget tokens and classes live in `styles/widgets/calendar.css` (weekstrip, day cells, columns, Activity cards) and must not fork the shared surface/accent system.

## 4a. Shared visual patterns

One implementation each, used by every screen. Domain components compose these; they do not restyle them.

| Pattern | Component | Contract |
|---|---|---|
| Identity image + fallback | `EntityHero` + `resolveHero` (`lib/hero.ts`) | The **only** image fallback chain: entity hero → other eligible entity media → category tone + icon from `--cat-*` → neutral. No hotlinked stock imagery, no second fallback list. Sizes follow §4 ratios. |
| Hero | `MediaHero` (generalized from `ProgramHero`) | 16:9 artwork with legibility scrim; back link, title (`--type-hero-title`), metadata line, one primary action, secondary actions, overflow. Program, Activity, Group, Profile. |
| Section heading | `SectionHeader` | `h2` (`--type-section-title`), optional one-line description, optional trailing action. No icon tile. |
| Content row | `ContentRow` (generalized from `ProgramActivityCard`) | 4:3 preview, content title, one metadata line, trailing action or chevron. Shows only real data; omits missing fields. Program Activities, Discover, editor, My Programs mobile. |
| Media rail / grid | `MediaGallery` (merges `ProgramMediaGallery` and `RelatedMediaRiver`) over `ThumbnailGrid`/`MediaItem` | Tiles from actual media only; video badge and duration only from asset metadata; opens `MediaViewer`. Empty state instead of placeholders. |
| Media viewer | `MediaViewer` | One viewer for all media. |
| People | `AvatarStack` | Real, permitted people only. Never decorative or stock faces. |
| Status | `StatusText` | Participation state label + `--color-status-*` dot. |
| Empty state | `EmptyState` | One sentence + one action (`13` §8). |
| Controls | `Button`, `Input`, `Select`, `SegmentedControl` (tabs), sheet/dialog | Token-styled; no per-page restyling of size, color or radius. |

**Truthful presentation:** shared components render only data the API returned. No invented counts, durations, schedules, media, people or verification marks; a missing value is omitted or shown as an empty state. Social proof uses real aggregates subject to the privacy rules in `12-SOCIAL.md`.

## 5. Shared interaction patterns

### Pattern A — One choice stage

```tsx
<Stage>
  <h1>What is your focus?</h1>
  <Grid className="grid-cols-2">
    {options.map(o => <OptionButton key={o.id} selected={value===o.id} onClick={() => choose(o.id)}>{o.label}</OptionButton>)}
  </Grid>
  {value==='other' && <input aria-label="Custom focus" />}
</Stage>
```

Selection may auto-advance if a single, low-risk choice and save succeeds. For multi-select, use a visible `Continue` button. A user can go Back without data loss.

### Pattern B — Workspace

```tsx
<Page>
  <Stack>
    <Row className="justify-between"><h1>My Strength Program</h1><StatusText status="draft" /></Row>
    <p className="text-xs text-muted">Workout · Strength · 8 weeks</p>
    <p className="text-xs text-muted">3 days/week · 24 program days</p>
    <Row><button className="btn btn--outline">Edit</button><button className="btn btn--outline">Calendar</button></Row>
    <Panel>
      <Row className="justify-between"><h2>Activities</h2><button className="btn btn--ghost">Add</button></Row>
      <p className="text-xs text-muted">3 activities · 8 instructions</p>
      {activities.map(a => <ContentRow key={a.id} title={a.title} meta={`${a.instructionCount} instructions · ${a.mediaCount} media`} />)}
    </Panel>
    <button className="btn btn--primary">Preview &amp; Publish</button>
  </Stack>
</Page>
```

The locked design is the authoritative source (`03-UX.md` §4); snippet demonstrates **primitive use**, not a complete page.

### Pattern C — Detail drawer

Use route-aware sheet/drawer for Activity Picker, video/media viewer, and instruction edit when screen space permits; on mobile use full-screen overlay. Preserve route origin and back behavior; browser Back closes overlay first. No nested modal more than one deep: navigate to full view if needed.

### Pattern D — Tiny media grid

Five or more small square thumbnails per row when width allows, with a final `+` tile. Thumbnails are independent, open one viewer, and support keyboard navigation. Avoid explanatory labels repeated under every thumb; metadata appears in viewer or hover/accessible names. Respect lazy loading and aspect crops.

### Pattern E — Session action button

At start of activity display `Start` as a primary button. Active → `Pause` and `Finish`; paused → `Resume` and `Finish`; finished → summary, with `Start again` explicit. Disable invalid transitions during pending API writes. Buttons are never decorative.

## 7. Typed minimal view models

Construct view models from API selectors before rendering: `ProgramWorkspaceVM` has header lines, counts, ordered activity rows and permission/action visibility; `CalendarItemVM` has date/time, title, thumbnail, state, origin, collaborator/unread indicators; `ActivityOccurrenceVM` has editable result fields, session controls, personal stat summaries, three media collections, optional collaborators/community stats. Avoid querying remote data in each Row/Panel. `ViewModel` fields are formatting, not canonical persistence.

## 8. Component extraction test

Before creating a new component, ask: (a) Is markup repeated at least twice with comparable structure? (b) Does it own meaningful reusable behavior, keyboard/focus logic, or accessibility? (c) Is its API **smaller** than copying the markup? If no, use primitive + semantic class / Tailwind locally.

**Anti-pattern:** `ProgramActivityMetricsPanel.tsx` importing `ActivityMetricSummaryCard.tsx` importing `MetricStatRow.tsx` importing `StatisticValue.tsx` to display three short values. Prefer one small Page component rendering `Grid` of values.

## 9. Testing the design system

- Visual regression at 390px, 768px, 1280px, dark and light, for Program page, Discover, My Programs, Activity Occurrence, Calendar, Program editor, Media Studio.
- Keyboard-only: selection, focus, sheet dismissal, session control, carousel, calendar move.
- Accessibility names for every icon-only control, image, status, timer and live recording indicator.
- Do not assert implementation component names in E2E; assert visible actions, order, and results.
- Performance: lazy thumbnails, paginate media, keep calendar scrolling smooth, avoid rendering entire media library on initial load.
- Themes: light and dark; reduced-motion disables transitions.
